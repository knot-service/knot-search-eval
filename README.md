# Knot 탐색 평가 어드민

합성 회의 문서와 사용자 사례로 로컬 Knot Spring 탐색을 실행하고 결과를 검수·비교합니다. 실제 회의 원문이나 운영 DB는 평가 데이터로 가져오지 않습니다.

## 접속

현재 설정된 Mac에서는 바탕화면의 **Knot 탐색 실험실.command**를 실행합니다. Docker Desktop이 실행 중이어야 합니다. 백엔드 코드를 수정한 뒤에는 **Knot 백엔드 변경 반영.command**를 실행해 로컬 Spring 이미지를 새로 만듭니다. 기존 워크스페이스·DB는 삭제하지 않습니다.

접속 주소는 `http://127.0.0.1:3000`입니다. 서버를 새로 시작한 터미널을 켜 두어야 합니다. 실행 환경은 이 컴퓨터 전용이며 Vercel 주소에서는 로컬 Spring 실행 기능을 사용할 수 없습니다.

구현은 `scripts/launch-local.command`를 참고하세요. 로컬 Spring 설정은 `backend/.env.search-local`에서, 평가 결과 DB 연결과 로그인 설정은 `.env.local`에서 읽습니다. 로컬 평가 DB(`127.0.0.1:55440/knot_eval`)와 Vercel 평가 DB는 별도 저장소이며 자동 동기화되지 않습니다. 로컬 DB의 검수 이력은 로컬에 남습니다. Vercel에서도 확인할 공개 실험은 합성 자료만 담은 `data/` artifact로 커밋하며, 최신 앱 버전이 배포되면 artifact를 읽기 전용으로 표시합니다. artifact는 Neon으로 가져오지 않습니다. 로컬 DB에는 `npm run import:live-qwen-local`로 같은 실행 기록을 멱등하게 가져올 수 있습니다. 이 명령은 `127.0.0.1:55440/knot_eval` 외의 DB에서 실행을 거부합니다. Spring이 검색하는 합성 문서는 별도의 로컬 PostgreSQL에 있습니다. 비밀값은 저장소나 실행 이력에 넣지 않습니다. 모델 서버의 이용 가능 여부에 따라 실제 실행이 실패할 수 있습니다.

2026-11-06 확인 시점에는 GitHub `main`에 게시 artifact가 푸시되어 있지만, 현재 Vercel 배포 응답에는 포함되지 않았습니다. 앱 버전·데이터 차이를 확인한 근거와 다음 조치는 [로컬·Vercel 동기화 확인](docs/local-vercel-sync-2026-11-06.md)에 기록했습니다.

## 실험과 검수

평가셋의 **회의록 형식 합성 실험 자료 · 검수 초안**에서 문서의 합성 원문, Markdown 본문, 자동 검토와 기대 동작을 확인합니다. 같은 생성 모델의 자동 검토는 사람의 판정이 아닙니다. 자동 검토가 보류한 문서는 사례를 직접 확인해 적합으로 검수하면 실행할 수 있습니다. 시간·장애·권한 등의 추가 조건이 미구현이면 별도로 실행을 보류합니다.

실험실에서 사례를 선택해 실행하면 사례별로 분리된 로컬 워크스페이스에 준비한 문서를 바탕으로 실제 Spring에 질문합니다. 답변, 문서 근거, 실행 시간, 실패 여부와 실행 이미지 식별자를 결과 저장소에 보존합니다. 응답 완료는 정답 판정이 아닙니다. 검색 후보 목록은 현재 Spring 응답에서 받지 않아 포함률을 계산하지 않습니다.

같은 사례를 다시 실행한 뒤 결과 상세의 **이전 결과와 비교**를 선택합니다. 서로 다른 평가셋·사례 입력·문서 조건은 같은 조건으로 표시하지 않습니다. 이전 대화, 특정 시각, 권한 변경과 장애 상태 등은 사례별로 재현 여부를 구분합니다.

## 개발 검증

```sh
npm install
npm run typecheck
npm test
npm run build
```

합성 회의록 생성에는 백엔드의 `generation-system.txt`, `generation-template.md`, `generation-schema.json`을 사용합니다. 생성 원본·자동 검토 결과·실험 로그는 Git 제외 경로인 `backend/resume/search-eval/`에 보관합니다.
