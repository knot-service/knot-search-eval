# 개발 Spring 탐색 평가 연결 계획

상태: 구현 중 · 2026-11-02

## 범위와 근거

평가 어드민에서 검수한 합성 사례를 개발 Spring API로 실행하고 이전 실행과 비교한다. 평가 결과 저장소는 기존 Neon을 사용한다. 사용자가 지정한 대상은 dev RDS의 Workspace 43이며, 그 안의 기존 데이터와 격리 방법은 아직 확인되지 않았다.

| 근거 | 확인 내용 | 구분 |
| --- | --- | --- |
| 사용자 요청 | dev 서버와 Workspace 43 사용 | 명시 요구 |
| backend `SearchQuestionController` | 첫 질문 및 후속 질문은 인증된 SSE API | 코드 관측 |
| dev API health와 OpenAPI | 서버 응답 및 후속 질문 경로 확인 | 현재 접속 관측 |
| `lib/state.ts`, `lib/schema.ts` | 잠긴 평가셋과 결과, 검수 및 비교 기반 존재 | 코드 관측 |
| Workspace 43 | 확인 당시 문서 0개·활성 멤버 1명. 이후 합성 문서 1개 추가 | 개발 DB 읽기 관측 |
| 개발 사이트 | 로그인된 세션에서 S01 합성 문서의 답변과 근거 카드 확인 | 수동 실행 관측 |
| 실행기의 인증 및 사례별 격리 | 연결 방식과 테스트 공간 범위 확인 중 | 미확인 |

## 흐름

사용자 실행 → 평가셋 버전·사례·실험 조건 확인 → 합성 문서와 대상 Workspace 일치 확인 → 개발 Spring에 인증된 질문과 후속 질문 전송 → SSE 종료 이벤트·답변·근거 수집 → Neon에 실행 조건과 결과 기록 → 같은 문서 조건의 이전 실행과 비교. 오류·중단·재현 불가능한 조건은 성공으로 표시하지 않는다.

## 책임

| 위치 | 책임 |
| --- | --- |
| `lib/schema.ts`, `lib/state.ts` | 평가셋·실행 결과 검증과 저장, 비교 가능 여부 |
| 새 Spring 실행기 | 실제 SSE 이벤트를 수신하고 결과와 오류를 분리 |
| 실험실 | 사례 선택, 실행 상태·결과 표시와 비교 진입 |
| dev Workspace 43 | 합성 문서와 실제 탐색 대상. 다른 자료를 지우거나 수정하지 않는다 |

## 데이터와 제약

사용자 데이터와 합성 사례가 섞이면 결과를 신뢰할 수 없다. 사례별 문서 범위를 서버가 제한할 수 있는지 또는 분리된 Workspace가 필요한지 확인한다. 인증 정보는 브라우저·저장소·실험 결과에 남기지 않는다. 날짜 고정, 권한, 장애를 재현할 수 없는 사례는 미실행으로 기록한다. 기존 데이터베이스의 스키마 변경은 현재 계획하지 않는다.

## 검증과 완료 기준

1. SSE 조각 분할·정상 종료·실패·시간 초과를 독립 테스트한다.
2. 격리된 합성 문서 준비와 실제 DB ID 매핑을 검증한다.
3. dev Spring에서 실제 한 사례를 성공 및 실패 경로로 실행하고, 실행 기록을 재조회한다.
4. 동일한 평가셋·문서 범위의 두 실행을 비교한다. 미검증 사례나 실험 조건이 다른 결과를 통과로 계산하지 않는다.

현재 구현: SSE 이벤트 파서와 dev API 요청 함수가 추가됐으며 로컬 자동 테스트로 파서·입력 검증을 확인했다. 어드민에서 실행하는 흐름과 DB fixture 자동화는 아직 연결하지 않았다. 수동 실행은 파서나 어드민 자동 실행의 실제 동작을 증명하지 않는다.


## 2026-11-02 로컬 Docker로 방향 변경

사용자 결정에 따라 로컬 Docker Spring을 기본 실험 환경으로 사용한다. dev Workspace 43의 문서는 변경하거나 삭제하지 않는다. 평가 결과 저장소와 Spring의 합성 문서 DB는 별도다. 기존 로컬 탐색용 DB에는 문서 100건이 있어 재사용하지 않는다.

- 분리된 로컬 Docker PostgreSQL과 현재 소스로 빌드한 Spring에서 health UP을 확인했다.
- 별도 합성 DB에 S01-01 문서 1개를 준비했고 실제 Spring SSE에서 답변과 근거를 확인했다.
- 평가 어드민 API로 S01-01을 두 번 실행해 로컬 결과 저장소와 기존 평가 결과 저장소(Neon)에 각각 저장했다. 두 실행의 문서 조건 해시가 같았다.
- 현재 자동 실행은 S01-01만 지원한다. 그 외 254개 사례는 격리된 입력, 대화 상태, 날짜, 장애 등의 재현 조건이 구현되지 않아 실행하지 않는다.
- 실행 시 전용 S01 평가셋을 따로 만들고 잠근 뒤 결과를 저장한다. 사용자가 검수 중인 기존 255개 사례 평가셋은 잠그지 않는다.
- 현재 실행은 로컬 전용이고 Vercel에서는 사용할 수 없다. 사례별 자동 적재, 실패 결과 저장, 모델 및 코드 버전의 자동 수집, 화면 QA는 후속 작업이다.
- 코드 리비전은 수동 입력이며 작업 트리 변경을 포함할 수 있으므로 전체 코드 증거로 취급하지 않는다.

## 회의록 형식 자료와 로컬 실험실

- 개발 DB의 문서 형식을 원문 없이 집계하고, 현재 백엔드의 회의록 생성 system prompt·template·schema를 사용해 합성 원문에서 생성했다. 기록: `backend/resume/search-eval/meeting-fixtures/quality-notes.md`.
- 사례 255개에 문서 878개를 조립해 격리 DB의 사례별 작업 공간에 모두 적재했다. 32개 사례는 문서가 없으며, 다량 자료 사례에는 여러 문서를 넣었다. 전사에만 있는 정보와 다른 Workspace의 문서 조건은 별도 합성 자료로 재현한다.
- 196개 문서에는 자동 검토 보류가 붙었다. 같은 모델의 자동 검토 통과도 사람 검수를 대체하지 않는다. 사례에 대한 사람의 적합 판정으로 문서 검토 보류를 해제할 수 있지만 시간·장애·대화 등 재현되지 않은 조건은 별도로 보류한다.
- 생성 문서의 중앙값은 89자로 개발 DB 문서의 1,044자보다 짧다. 무리하게 대화를 늘린 실험에서는 원문에 없는 구체적 결정이 추가돼 사용하지 않았다. 긴 문서·현실적인 내용 분포는 추가 작업이 필요하다.
- 사례별 입력을 DB에서 적재 전후 검증하고, 각 실행에 응답 상태·답변·근거·시간과 실행 컨테이너 이미지 식별자를 저장한다. 검색 후보는 미수집으로 표시한다. 답변 완료는 품질 통과가 아니다.
- 초기 단문 자료 120개 실행은 이전 결과로 남겨두었으나 새 회의록 자료와 비교 가능한 동일 입력은 아니다.

## 2026-11-06 실험 결과 게시 경로 정리

후속 결정에 따라 위의 Neon 쓰기·공유 DB 설명은 현재 운영 흐름에 적용하지 않는다. 로컬 `knot_eval`이 편집 가능한 실험·사람 검수의 기준 저장소이며, Vercel DB(Neon)는 이 로컬 DB와 별개다. 로컬 결과를 Vercel에서 확인하기 위해 전체 로컬 DB를 복제하거나 Neon에 실험 데이터를 쓰지 않는다.

- 실제 Lab HTTP/SSE 관측은 `data/live-qwen-http-sse-2026-11-06.json`에 합성 자료와 실행 기록으로 보존한다.
- 로컬 가져오기 스크립트는 `127.0.0.1:55440/knot_eval`만 허용하며 평가셋·세 실행을 멱등하게 적재한다.
- Vercel은 커밋된 artifact를 응답 state에 읽기 전용으로 합친다. 이 overlay는 Neon에 dataset/run 행을 기록하지 않으며, 게시된 실행의 사람 검수는 로컬에서만 허용한다.
- 이 관측은 합성 문서 두 건, 실제 Qwen, Lab API/SSE를 썼다. 단일 요청 관측이므로 A/B·p95/p99 근거로 사용하지 않는다. 자세한 결과와 한계는 `docs/live-qwen-http-sse-2026-11-06.md`에 있다.
