# 탐색 평가 어드민 구현 계획

상태: 구현 중 · 2026-11-02. 별도 비공개 저장소 `knot-service/knot-search-eval`과 개인 Vercel 계정 대상. Knot 운영 DB·모델 설정 변경은 범위 밖이다.

## 범위와 근거

- [#1084](https://github.com/woowacourse-teams/2026-knot/issues/1084): 합성 사례, 사람 평가, 보안 필수 통과, 품질·지연·비용의 기준을 제공한다. 이 사이트 자체가 이슈의 모든 평가 완료를 뜻하지 않는다.
- [탐색 개선 제안](https://app.notion.com/p/408b43517522811d953fcc4def215825): S01~S76은 기대 동작이며 실행 또는 통과 증거가 아니다. 원문 검색은 범위 밖이다.
- Figma `327:748`, `327:37`은 읽기 전용 디자인 참고다. 밝은 회색·흰색·보라색, 좌측 탐색 및 정보 중심 화면을 적용한다.
- 새 프로젝트로 기존 코드가 없으며 Vercel 인증과 별도 지속 저장소는 연결 환경 확인 전 미정이다.

## 흐름과 책임

평가자 인증 → 합성 평가셋 및 사례 조회·검수 → 잠긴 버전 기준 수동 실험 결과 가져오기 → 실행별 결과·실패와 양쪽 비교. 자동 실행과 실제 회의 자료는 제외한다. 인증 실패와 저장소 장애는 성공으로 표시하지 않는다.

| 제안 위치 | 책임 |
|---|---|
| 앱 화면 | 데이터셋·시나리오·실행·비교·검수 흐름 |
| 인증 경계 | 개인 평가자 세션 및 모든 데이터 API 보호 |
| 데이터 검증 | 파일 형식·ID·중복·버전·잠금·실패 상태 검증 |
| 별도 지속 저장소 | 평가셋 버전, 합성 결과, 검수 이력 보존. 환경변수 없으면 저장하지 않고 오류 안내 |

## 데이터와 검증

평가셋·사례·실험·결과·검수 이력을 별도 저장소에 보존한다. 잠긴 평가셋은 변경하지 않고 새 버전에서 변경한다. 요청 중복·잘못된 JSON·다른 평가셋·로그인 실패를 확인한다. 운영 DB는 사용하지 않는다. 실제 저장 기술과 개인 Vercel 계정의 제공 범위는 확인 후 연결한다.

## 단계

1. 입력 검증과 합성 예제 및 단위 테스트.
2. 인증·데이터 API의 성공·거부·저장 실패 테스트.
3. Knot 디자인을 참고한 목록·상세·비교·검수 화면 및 파일 가져오기.
4. 실제 브라우저에서 주요 사용자 흐름과 무인증 접근 점검.
5. 비공개 저장소 및 Vercel 배포·지속 저장소 연결. 계정·요금·인증 제약은 검증 후 보고.

완료는 로그인한 평가자가 합성 자료를 불러오고 검수해 새로고침 후 유지하며, 동일 조건 결과와 실패를 비교할 수 있고 무권한 요청이 차단된 것을 확인했을 때다. 실험 실행 및 실제 회의 자료는 후속 범위다.
