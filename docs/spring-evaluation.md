# Spring 탐색 회귀 평가 연결 계획

평가 대상은 모델 단독 호출이 아니라 Knot Spring 서버의 실제 탐색 API다. 평가셋은 합성 자료이며 각 사례와 기대 동작은 사람 검수 전 초안이다. 자동으로 만든 변형은 독립적으로 검수해야 한다.

## 실행 계약

1. 운영·개발 DB와 분리된 평가 전용 PostgreSQL에 사례별 Workspace와 합성 문서를 준비한다. 문서의 실제 DB ID와 평가셋 ID의 대응을 기록한다. 기존 Workspace나 사용자 데이터를 수정하지 않는다.
2. 평가 대상 Spring 서버의 버전과 설정, 모델, 평가셋 버전 및 문서 데이터의 해시를 기록한다. 같은 조건에서 이전 결과와 비교한다.
3. 인증된 `POST /api/v1/workspaces/{workspaceId}/search/conversations` 요청으로 첫 질문을 전송하고 SSE의 `delta`, `evidence`, `completed`, `failed`, `stopped`를 수집한다. 후속 질문은 같은 대화의 질문 API를 이용한다.
4. 응답 내용, 실제 근거, 종료 상태, 지연을 저장하고 기대 동작과 함께 보여준다. 텍스트가 유사하다는 이유만으로 통과 처리하지 않는다. 불확실한 판정은 사람 검수 대상으로 둔다.
5. 시간 고정, 권한 변경, 장애 주입 등 사례 전제 조건을 재현하지 못하면 실행 불가로 명시한다. 정상 요청 결과를 장애 실험 결과로 취급하지 않는다.

## 현재 상태

- 평가셋의 질문·예상 동작·합성 문서는 평가 어드민에 보관한다. 아직 Spring의 검색 DB에 자동으로 적재되지 않는다.
- Spring API 실행, 합성 문서 자동 적재, 이전 실행과의 실제 자동 비교는 아직 구현하거나 검증하지 않았다.
- 모델 서버의 헬스 응답은 확인했지만 실제 모델 추론과 Spring 연결은 검증하지 않았다.
- Vercel에서 개인 컴퓨터의 localhost를 직접 호출할 수 없다. 로컬 실행기 또는 접근 제어가 된 별도 실행 환경이 필요하다.
